# 要件定義書：デスクトップペット育成シミュレーション

## 1. 概要・コンセプト

デスクトップ上に常駐する小さなペット（キャラクター）が、機嫌・満腹度・体力などのステータスを持ち、時間経過とともに変化していく育成シミュレーションアプリ。ユーザーは日常的にPCを使う中で、餌やり・会話・ミニゲームなどの短い触れ合いを繰り返し、ペットを育てていく。

- 常駐型・放置系：バックグラウンドで時間経過によりステータスが変化し続ける
- 低コミットメント：1回の操作は数秒〜数十秒で完結し、作業の合間に触れ合える
- カジュアルで実装の着手感が軽く、個人開発の練習題材として段階的に機能を積み上げやすい

## 2. 想定ユーザー・ユースケース

### 想定ユーザー
- PCで作業する時間が長い個人（学生・エンジニア・リモートワーカーなど）
- デスクトップマスコット／たまごっち系アプリに親しみがある層
- 本アプリの場合は開発者自身が最初のユーザー（自分で使う前提のMVP）

### ユースケース例
- 作業の休憩中にペットの様子を確認し、餌をやる・話しかける
- 満腹度や機嫌が下がっているとき、通知やペットの見た目変化で気づく
- 気分転換にミニゲームをプレイしてペットと遊ぶ
- 数日〜数週間育てて、ペットが成長・進化していく過程を楽しむ

## 3. 主要機能

### 3.1 MVP範囲
- デスクトップ上に常駐する小さなウィンドウ（透明背景・最前面表示）でペットを表示
- ペットのステータス管理：機嫌・満腹度・体力の3種類程度
  - 時間経過で自動的に減少（満腹度・機嫌）、イベントで回復
- 基本アクション：
  - 餌やり（満腹度回復）
  - 会話（簡単なメッセージのやり取りで機嫌回復）
  - なでる／クリックで簡単な反応
- ステータスの可視化（アイコン・ゲージ・ペットの表情変化など）
- ステータスの永続化（アプリを終了・再起動してもデータが保持される）
- 簡易設定画面（通知のON/OFF、常駐ウィンドウの位置リセットなど）

### 3.2 拡張候補（MVP後）
- ミニゲーム（反応速度ゲーム、簡単なパズルなど）でステータス回復や経験値獲得
- 進化・成長システム（見た目やステータス上限の変化）
- イベント機能（誕生日、季節イベント、ランダムイベント）
- 会話機能の強化（LLM連携による自由会話、雑談応答）
- 通知機能（お腹が空いた、機嫌が悪いなどのOS通知）
- 複数ペット・コレクション要素
- 外部データ連携（カレンダー連携でイベント生成、作業時間連動の報酬など）

## 4. 画面構成・UI要素

- **GUIフレームワーク想定**：PySide6（Qt for Python）
  - 常駐ウィンドウには `Qt.FramelessWindowHint` + `Qt.WindowStaysOnTopHint` + 背景透過（`setAttribute(Qt.WA_TranslucentBackground)`）を使用し、デスクトップ上に「キャラクターのみ」が浮いているように見せる
  - システムトレイアイコン（`QSystemTrayIcon`）から、ステータス確認・設定・終了などの操作を行えるようにする
- **主要画面／ウィンドウ**
  1. 常駐ペットウィンドウ：ペット本体の表示、クリック／ドラッグでの簡単な反応
  2. ステータスパネル（ポップアップ or サブウィンドウ）：機嫌・満腹度・体力をゲージ表示
  3. アクションメニュー：右クリックまたはトレイメニューから「餌やり」「会話」「ミニゲーム」「設定」などを選択
  4. 会話ウィンドウ：簡易チャット風のUIでペットとやり取り
  5. 設定ウィンドウ：通知設定、ウィンドウ位置リセット、データリセットなど
- ペットのドラッグ移動、画面端へのスナップなど、常駐アプリらしい挙動も検討

## 5. 技術スタック

| 項目 | 候補 |
|---|---|
| 言語 | Python 3.11+ |
| GUIフレームワーク | PySide6（Qt for Python） |
| ステータス管理 | アプリ内のステータス管理クラス（`PetState`）＋ `QTimer` による定期更新 |

| テスト | pytest（ステータス変化ロジックなどのユニットテスト） |

## 6. データ構造

### 6.1 ペットステータス（例：JSON）

```json
{
  "pet_id": "pet_001",
  "name": "ぽちこ",
  "created_at": "2026-10-09T10:00:00",
  "last_updated": "2026-10-09T15:30:00",
  "level": 3,
  "status": {
    "mood": 78,
    "hunger": 45,
    "stamina": 90
  },
  "evolution_stage": "child",
  "settings": {
    "notifications_enabled": true,
    "window_position": [1200, 650]
  }
}
```

### 6.2 イベント履歴（例：JSON Lines もしくは配列）

```json
{
  "timestamp": "2026-10-09T15:00:00",
  "event_type": "feeding",
  "detail": "おやつをあげた",
  "status_delta": {"hunger": 20, "mood": 5}
}
```

- イベント履歴は配列として1ファイルに保存、または日付ごとにファイル分割
- 将来的にSQLiteへ移行する場合は `events` テーブル（id, timestamp, event_type, detail, status_delta）を想定

## 7. Claude Codeのagent/skill/hookの活用案

本プロジェクトはClaude Codeの機能を使った開発練習も目的としているため、以下のような対応を想定する。

| Claude Code機能 | 活用案 |
|---|---|
| **sub-agent** | ペットとの会話応答を専用のsub-agentに担わせる。会話ログやペットの性格設定を渡し、キャラクターらしい返答を生成するエージェントとして分離する |
| **sub-agent** | ミニゲームのロジック実装やUIレイアウト調整など、機能単位の実装作業を専用agentに委任し、並行して開発を進める |
| **skill** | 「イベント生成スキル」：誕生日・進化・季節イベントなどの発生条件や内容をスキルとして定義し、一定条件で呼び出す |
| **skill** | 「ステータスバランス調整スキル」：満腹度・機嫌の減少速度やミニゲームの報酬バランスを検証・調整する作業をスキル化する |
| **hook** | アプリ起動時・終了時のhookで、最終起動時刻を記録し、非起動中の時間経過をステータスに反映する処理を自動化する |
| **hook** | コミット前hookで、ステータス管理ロジックや永続化処理に対するユニットテストを自動実行する |

## 9. 開発上の懸念点・リスク

- **常駐ウィンドウの実装難易度**：OSごとの透過ウィンドウ・最前面表示の挙動差（特にWindows/macOSでの見た目や挙動の違い）に注意が必要
- **時間経過の扱い**：アプリが起動していない間の時間経過をどう反映するか（最終起動時刻との差分計算が必要）の設計をMVP初期に固めておく必要がある
- **スコープの肥大化**：会話機能やミニゲームなど拡張候補が多く、MVPの範囲を明確に線引きしないと着手が重くなる恐れがある
- **データ破損・マイグレーション**：JSONファイルの手動編集や破損時の挙動、将来的なデータ構造変更時の後方互換性を考慮する必要がある
- **パフォーマンス**：常駐アプリとして長時間起動し続けるため、メモリリークやタイマー処理の負荷に注意する
- **一人開発での継続性**：練習目的も兼ねるため、Claude Codeのagent/skill/hookをどこまで使うかの判断が開発速度に影響する可能性がある
