# ペイントツールアプリ 要件定義書

## 1. 概要・コンセプト

キャンバス上に自由に描画できる、デスクトップ向けのペイント／お絵かき・画像編集ツール。
シンプルな手描きツールとしてすぐ使えることを最優先にしつつ、レイヤー・ブラシ・フィルタ・エクスポート形式などを段階的に拡張していける設計にする。

- **実用性**: 日常的なちょっとした絵の作成、画像への加筆、アイコン作成などに使える完成度を目指す。
- **拡張性**: 機能追加のたびに大きな書き直しが発生しないよう、ツール・フィルタ・レイヤーなどを疎結合なモジュールとして実装する。
- **開発者本人の練習台**: 単なるアプリ開発ではなく、Claude Codeのsub-agent／skill／hookを使った開発フローを試す場としても活用する。

本ドキュメントは複数のアプリ案を比較検討するための要件定義（試作段階）であり、この時点では実装には着手しない。

## 2. 想定ユーザー・ユースケース

### 想定ユーザー
- ちょっとしたイラストやメモ書きを描きたい個人ユーザー
- 既存画像に手描きで加筆・修正したいユーザー（スクリーンショットへの注釈など）
- アイコンやシンプルなドット絵・ロゴ素材を作りたいユーザー
- 開発者自身（Claude Codeの機能を試す検証用アプリとしての利用）

### 主なユースケース
1. 新規キャンバスを開いて、ブラシで自由に描画し、PNGとして保存する。
2. 既存の画像ファイルを読み込み、レイヤーを重ねて加筆・注釈を入れる。
3. 複数レイヤーを使って下書き・線画・着色を分けて管理する。
4. フィルタ（モノクロ化、ぼかし等）を適用して画像を加工する。
5. 作業中のプロジェクトファイルを保存し、後日再編集する。

## 3. 主要機能

### 3.1 MVP（必須機能）
- **キャンバス機能**
  - 新規キャンバスの作成（サイズ指定）
  - 既存画像（PNG/JPEG）の読み込み
  - ズーム・パン（表示位置の移動）
- **描画ツール**
  - 基本ブラシ（線の太さ・色の指定）
  - 消しゴム
  - 塗りつぶし（バケツ）
  - 直線・矩形・円などの簡易図形描画
  - カラーピッカー（色選択）
- **レイヤー機能**
  - レイヤーの追加・削除・並び替え
  - レイヤーの表示/非表示切り替え
  - レイヤーの不透明度設定
  - レイヤーの結合
- **編集操作**
  - 元に戻す／やり直す（Undo/Redo）
  - キャンバスのクリア
- **ファイル操作**
  - プロジェクトファイルとしての保存・読み込み
  - PNG/JPEGへのエクスポート

### 3.2 拡張候補（MVP後の段階的追加）
- フィルタ機能（モノクロ、ぼかし、シャープ、色調補正など）
- 自動彩色・線画抽出などの画像処理支援（AI/画像処理ライブラリ連携）
- ベクター描画機能（パス編集、拡大縮小に強い図形オブジェクト）
- テキスト挿入機能
- カスタムブラシ（ブラシの質感・筆圧対応）
- ペンタブレット（筆圧感知）対応
- レイヤーグループ化、レイヤーマスク
- 画像の自動バックアップ・バージョン履歴管理
- プラグイン的な拡張機構（独自フィルタ・ツールの追加）
- アニメーション機能（簡易なフレームアニメーション）
- クラウド保存・複数デバイス間の同期

## 4. 画面構成・UI要素

GUIフレームワークとしてPySide6を想定した画面構成。

```
+--------------------------------------------------------------+
| メニューバー（ファイル / 編集 / 表示 / フィルタ / ヘルプ）      |
+----------------+------------------------------+--------------+
| ツールパレット  |                              | レイヤー     |
| - ブラシ        |                              | パネル      |
| - 消しゴム      |         キャンバス            | - レイヤー   |
| - 塗りつぶし    |      （描画エリア）           |   一覧      |
| - 図形          |                              | - 追加/削除  |
| - カラーピッカー |                              | - 不透明度  |
+----------------+------------------------------+--------------+
| ステータスバー（ズーム倍率・カーソル座標・現在のツール表示など）  |
+--------------------------------------------------------------+
```

- **メニューバー**: ファイル操作（新規/開く/保存/エクスポート）、編集（Undo/Redo）、フィルタ適用など
- **ツールパレット**: 左側または上部に配置し、アイコンで各ツールを選択
- **キャンバス**: 中央に配置、ズーム・パン操作に対応
- **レイヤーパネル**: 右側に配置し、レイヤーの一覧・表示切替・不透明度スライダーなどを表示
- **カラーパレット/カラーピッカー**: ツールパレット内または専用ダイアログ
- **ステータスバー**: 現在のズーム倍率、カーソル座標、選択中ツールなどを表示

## 5. 技術スタック

| 分類 | 候補 | 用途 |
|---|---|---|
| GUIフレームワーク | PySide6 (Qt for Python) | ウィンドウ・ウィジェット・イベント処理 |
| 画像処理 | Pillow | 画像の読み込み・保存・基本的なフィルタ処理 |
| 数値処理 | NumPy | ピクセル単位の演算、フィルタ処理の高速化 |
| 描画エンジン | QPainter / QImage（PySide6標準） | キャンバス上のリアルタイム描画 |
| ファイル保存形式（画像） | PNG, JPEG, BMP | 汎用的な画像エクスポート |
| ファイル保存形式（プロジェクト） | 独自形式（例: `.pnt`、ZIP+JSON構成） | レイヤー構成を保持した保存・再編集用 |
| 設定・メタデータ | JSON | アプリ設定、プロジェクトのメタ情報 |
| バージョン管理（開発側） | Git | ソースコード管理 |
| テスト | pytest | 単体テスト |

## 6. データ構造

### 6.1 レイヤー構成（メモリ上のモデル例）

```
Project
 ├─ canvas_size: (width, height)
 ├─ layers: List[Layer]
 │    ├─ Layer
 │    │   ├─ id: str
 │    │   ├─ name: str
 │    │   ├─ image_data: NumPy配列 or QImage
 │    │   ├─ opacity: float (0.0〜1.0)
 │    │   ├─ visible: bool
 │    │   ├─ blend_mode: str（将来拡張用: 通常/乗算/加算など）
 │    │   └─ order: int（描画順）
 └─ metadata
      ├─ created_at: datetime
      ├─ updated_at: datetime
      └─ author: str
```

### 6.2 プロジェクトファイルの保存形式

- 独自拡張子（例: `.pnt`）を持つZIPアーカイブ形式を想定
  - `project.json`: キャンバスサイズ、レイヤー順序、メタデータなどの情報
  - `layers/layer_<id>.png`: 各レイヤーの画像データ（PNG形式でロスレス保存）
- この形式により、レイヤー構造を保ったまま保存・再編集が可能になる
- 最終出力（配布・共有用）は通常のPNG/JPEGとしてフラット化してエクスポート

## 7. Claude Codeのagent/skill/hook活用案

開発練習の観点から、以下のような活用を想定する（いずれも実装は本ドキュメントの対象外、将来の開発フェーズでの構想）。

| 種類 | 活用案 | 具体例 |
|---|---|---|
| **Agent（サブエージェント）** | 画像処理・提案系の複雑なタスクを委任 | 「自動彩色の候補を提案するagent」「画像補正（明るさ・色調）の最適値を分析して提案するagent」「コードレビュー専用agent」 |
| **Skill** | 定型的な処理・テンプレートの呼び出し | 「特定のフィルタ（モノクロ化、ぼかし等）を適用するskill」「新規ツールクラスのボイラープレートを生成するskill」「プロジェクトファイル形式のバリデーションskill」 |
| **Hook** | 保存・編集などのイベントに連動した自動処理 | 「ファイル保存時に自動バックアップを作成するhook」「一定回数の編集操作ごとにバージョンスナップショットを保存するhook」「コミット前にlint/testを走らせるhook」 |

これらはアプリ自体の機能ではなく、開発プロセスを支援する仕組みとして位置づける。たとえば「保存時の自動バックアップ」はアプリ側の機能としても、Claude Code開発環境のhookとしても実現しうるため、どちらで実装するかは開発フェーズで検討する。

## 8. 拡張ロードマップ（段階的な追加イメージ）

1. **フェーズ0（本ドキュメント）**: 要件定義・技術選定の検討
2. **フェーズ1（MVP）**: キャンバス、基本ブラシ/消しゴム、レイヤー基本機能、Undo/Redo、PNG保存・読み込み
3. **フェーズ2**: フィルタ機能の追加（モノクロ、ぼかし、シャープ等）、独自プロジェクトファイル形式の実装
4. **フェーズ3**: カスタムブラシ、テキスト挿入、レイヤーマスク・グループ化
5. **フェーズ4**: 自動彩色・線画抽出などの画像処理支援機能（AI活用）
6. **フェーズ5**: ベクター描画機能、ペンタブレット（筆圧）対応
7. **フェーズ6**: バージョン履歴管理、プラグイン機構、アニメーション機能など発展的な拡張

## 9. 開発上の懸念点・リスク

- **描画パフォーマンス**: レイヤー数や解像度が増えると、リアルタイム描画・再描画処理が重くなる可能性がある。NumPy/QImageでの効率的な差分更新を検討する必要がある。
- **Undo/Redoの実装コスト**: レイヤー・ピクセル単位の変更履歴を保持する仕組みは、メモリ使用量とのトレードオフになる（全体スナップショット vs 差分記録）。
- **ファイル形式の互換性**: 独自プロジェクト形式を採用する場合、将来の仕様変更に対する後方互換性の確保が課題になる。
- **一人開発であることによるスコープ肥大化**: 拡張候補が多いため、MVPの範囲を明確に線引きし、段階的にしか機能を増やさない規律が必要。
- **GUIフレームワークの学習コスト**: PySide6（Qt）のイベント処理・描画モデルに不慣れな場合、初期の学習コストがかかる。
- **Claude Code機能活用の検証コスト**: agent/skill/hookの活用は開発プロセスの実験でもあるため、本来のアプリ開発と並行して試行錯誤する時間が必要になる。
