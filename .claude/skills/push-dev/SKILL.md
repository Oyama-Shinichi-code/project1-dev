# push-dev

現在の作業ディレクトリの変更を検証用リポジトリ (`dev`) に反映する。

## 手順
1. `git status` で変更内容を確認する。コミットされていない変更がなければ、その旨をユーザーに伝えて終了する。
2. `git status` の内容を確認し、`.env` 等の秘密情報を含むファイルが含まれていないか確認する。含まれていた場合はユーザーに警告し、除外の指示を待つ。
3. `git add -A` でステージし、変更内容から簡潔なコミットメッセージ（「なぜ」を中心に）を生成して `git commit` する。コミットメッセージの最後に `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>` を付ける。
4. `git push dev main` を実行する（`main` ブランチのデフォルト upstream は `dev` だが、明示指定して確実に検証用リポジトリへ反映する）。
5. 結果（コミットハッシュ、push先URL）を簡潔に報告する。

## 注意
- 本番リポジトリ (`origin`) には絶対にpushしない。本番への反映は `/push-all` を使う。
- コミット対象に迷う変更（大きなバイナリ、意図不明なファイル等）があれば、pushする前にユーザーに確認する。
